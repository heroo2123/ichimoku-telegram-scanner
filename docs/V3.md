# Ichimoku Scanner V3.1

V3 turns the Telegram scanner into a decision, research, and paper-trading platform while preserving the existing transparent Ichimoku rules.

## Production flow

1. **Crypto scan:** 00:17 UTC, after the Binance daily candle closes.
2. **US scan:** 23:17 UTC Monday–Friday, after the completed US cash session.
3. Both scans queue signals without Telegram delivery.
4. **Telegram delivery:** 12:00 UTC / 15:00 Kuwait every day, with an idempotent quiet catch-up at 12:20 UTC.
5. V3 persists signals, lifecycle events, regimes, risk plans, backtests, and paper portfolio state to Supabase when configured. JSON files under `data/v3_*.json` provide a fallback.

Before Telegram delivery, every claimed queue row is reconciled with its authoritative Supabase lifecycle state. Invalidated/completed signals are cancelled, extended signals remain visible in the dashboard and full CSV, and up to ten actionable signals appear in one ranked digest. The top three receive detailed charts. A successful digest or CSV receipt completes each row exactly once; failed rows remain retryable.

## Features

- Signal lifecycle: confirmed, entry-zone, extended, active, invalidated, completed
- ATR/Kijun/cloud entry and invalidation plans
- Correlation and cluster-concentration warnings
- US and crypto market-regime snapshots
- Historical backtesting using the exact scanner calculation functions
- Look-ahead-safe 1/3/5/10/20-session outcomes
- Statistical logistic calibration after enough results exist
- Informational 4-hour timing context for already-qualified daily signals
- Paper portfolio with risk-based sizing and cluster limits
- FastAPI dashboard and Telegram command webhook
- Stale/invalid OHLCV rejection and split-adjusted US data
- Durable scanner run and delivery-queue health records
- NYSE-session-aware lifecycle tracking and batched provider refreshes
- Walk-forward score calibration and cost-aware next-open backtests

## Environment variables

### GitHub Actions

- `TELEGRAM_BOT_TOKEN`
- `TELEGRAM_CHAT_ID`
- `SUPABASE_URL`
- `SUPABASE_SERVICE_ROLE_KEY`

`SUPABASE_SERVICE_ROLE_KEY` accepts either the modern `sb_secret_...` server key or the legacy JWT-based service-role key. Modern secret keys are sent only through the Supabase `apikey` header.

### Render dashboard

- `SUPABASE_URL`
- `SUPABASE_SERVICE_ROLE_KEY`
- `DASHBOARD_API_KEY`
- `TELEGRAM_BOT_TOKEN`
- `TELEGRAM_CHAT_ID`
- `TELEGRAM_WEBHOOK_SECRET`

Never expose the Supabase secret/service-role key in browser code. The dashboard uses it only on the server.

## Safety

V3 does not execute real trades. Paper trading is enabled only as a simulation. The rule-based grade remains visible even when statistical calibration becomes available.
